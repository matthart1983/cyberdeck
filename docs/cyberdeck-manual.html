Layer 01 · niri

Windows scroll, they don't stack

niri is a scrollable tiler: workspaces are an endless row of columns you scroll along, not a tree you subdivide. Gaps are 10px and the top strut is nobody's problem — Waybar declares its own exclusive zone, so niri gets out of its way without a hand-counted offset.

Config linux/niri/config.kdl Layout scrolling columns Modifier Super, not Alt
Why Super

Every alt bind from the macOS side is Mod (Super) here. On Linux alt+<letter> is the GTK mnemonic accelerator — binding it would make every application's menu bar unreachable.

No grant

There is no Accessibility permission on this side, and nothing to click through. Log out, pick niri at the session chooser, and it comes up with Waybar already running — spawn-at-startup handles the bar and the wallpaper.

No tree

AeroSpace's balance-sizes and flatten-workspace-tree have no counterpart, because there is no tree: columns scroll instead of nesting. Mod+shift+r cycles the preset widths, which is the nearest thing to "reset the layout".

Layer 02 · SketchyBar + JankyBorders

The bar reads your own network

macOS's menu bar is hidden; SketchyBar replaces it with 18 items. The interesting part: the net and link items aren't shelling out to netstat and ping — they scrape netwatch's own daemon.

Config macos/sketchybar/sketchybarrc Feed 127.0.0.1:9464 Cost 0.4% CPU · 15MB

What's up there

spaces
Live AeroSpace workspaces — the focused one glows magenta
front_app
Whatever app currently has focus
cpu · mem · disk
System vitals a shell plugin each — top, memory_pressure and df have to be parsed
net
Throughput up and down from netwatch, not netstat
link
Gateway RTT, DNS RTT, loss ratio, live connection count
battery · clock
The usual suspects, in the palette

Driving it

brew services restart sketchybarRestart the bar after a config edit
sketchybar --reloadReload without a full restart
curl -s 127.0.0.1:9464/metricsRead the raw feed the bar is drinking from
launchctl kickstart -k gui/501/io.matt.netwatch-metricsRestart the netwatch daemon behind it
Gotcha

launchctl bootout is asynchronous — bootstrapping straight after it races the teardown and fails silently. Always kickstart a service that's already loaded rather than cycling it.

Borders

JankyBorders draws the magenta glow on the focused window and a dim purple on the rest. It's launched by macos/bin/borders.sh and needs no permissions.

Layer 02 · Waybar

The bar reads your own network

Same claim, seven items instead of eighteen, and only two of them need a script. cpu, memory, disk and battery each wanted a shell plugin on macOS purely because top, memory_pressure and pmset have to be parsed; Waybar reads all four out of /proc and /sys itself. What's left in scripts/ is link and net — the netwatch-fed pair, which was always the part worth having.

Config linux/waybar/config.jsonc Feed 127.0.0.1:9464 Scripts 2 of 7

Driving it

waybarRun it in a terminal to see why it won't start

Reload

Waybar reloads on SIGUSR2, and install.sh sends it only on a run that actually rewrote something under ~/.config/waybar. A re-link that changed nothing leaves the bar alone.

No borders daemon

JankyBorders has no counterpart here and needs none: niri draws its own focus-ring, magenta on focus and purple at rest, from the same two palette entries. That is one fewer daemon on this side, not a missing feature.

Layer 03 · Ghostty

One terminal, always a keystroke away

Ghostty at 88% opacity with a 26px blur — the translucency is most of what makes the rice read as cyberpunk. Everything above the keybinds is one shared config; common/ghostty/platform-{macos,linux}.conf holds the half that can't be.

Why shift

Every cmd bind from the macOS half becomes ctrl+shift here. The shift is not decoration: plain ctrl+d is EOF and ctrl+c is SIGINT, and a terminal that eats either one is broken.

Checking it

ghostty +validate-configExits 0 when the config parses
ghostty +show-configSee every value as actually resolved
ghostty +list-fontsConfirm a font is visible to Ghostty
First run

The quick terminal is a global hotkey, so macOS asks for Accessibility permission the first time you press it. Grant it once and it stays.

Getting it installed

linux/ghostty.shBuild the pinned release from upstream's signed tarball into ~/.local
GHOSTTY_VERSION=1.3.2 linux/ghostty.shMove to a different release
Not packaged

Fedora doesn't ship Ghostty and its filtered Flathub doesn't carry it, so the only prebuilt binaries are third-party COPRs — which packages.sh refuses to pick for you. linux/ghostty.sh checks the tarball's minisign signature before unpacking it, and reads the required Zig version out of the source it just verified: Fedora ships two Zig minors and only one of them can build Ghostty.

No global hotkey

GTK has no system-wide hotkey API, so global: binds don't work on this side. The compositor owns that job instead — Mod+return in config.kdl spawns Ghostty. The dropdown itself still works, from inside the terminal.

One config

There is no platform half of tmux.conf. It picks the clipboard with if-shell 'command -v wl-copy' at config-load time, so the same file yanks to pbcopy on one machine and wl-copy on the other.

Careful

Panes are 1-indexed here, so scripts targeting session:window.0 will fail. Use named targets — {left}, {top-right} — the way bin/hud does.

Layer 07 · Zed, Claude Code, atuin

Where the palette gets quieter

Zed keeps the neon chrome but its syntax colours are deliberately desaturated. Chrome is glanced at; code is read for hours, and full-saturation magenta on black is exhausting at that duration.

Zed common/zed/themes/cyberpunk-neon.json Scopes 35 Claude dark-ansi

What each app does

ZedCustom theme — neon UI, calm syntax, JetBrainsMono buffers
Claude Codedark-ansi theme, so it inherits Ghostty's palette instead of duplicating it
atuinThemed history UI, since ctrl+r takes over the whole screen
common/bin/cc-statuslineModel ▸ directory ▸ git branch ▸ context pressure
Why ANSI

Setting Claude Code to dark-ansi means it renders through the terminal's own 16 colours. Change the Ghostty theme and Claude follows automatically — there's no second palette to keep in sync.

Selected, not just linked

Linking a theme into ~/.config/zed/themes only puts it in Zed's picker — Zed keeps rendering One Dark until settings.json names it. install.sh now writes that key. It splices the value into the file's text rather than re-serialising it, because Zed's settings are JSONC and a json.dump round-trip would hand you back your settings with every comment deleted.

Two palettes

Both live in every palette: the chrome slots, and the thirteen CP_SOFT_* that only syntax uses. Anything new should pull from a slot rather than inventing a colour — test/theme.sh fails on a literal hex left in a template, because a literal is a colour that stops following the theme.

Layer 08 · macOS

Everything here is reversible

The system layer is the only part that reaches outside the dotfiles, so it was built undo-first: snapshot before apply, and a restore script that replays the snapshot back into the defaults system.

Layer 08 · Fedora

There is nothing to put back

The macOS half needs a snapshot because defaults write mutates settings you can't otherwise recover. This side has no equivalent to undo: the Fedora layer installs packages and enables two services, and that is the whole of its reach. Uninstalling is dnf remove.

What it touches

tuned-ppd
Enabled, for the power profiles GNOME reads see the note below
fwupd

Desktop
Nothing. niri replaces GNOME at the session chooser rather than reconfiguring it
Conflict

packages.sh deliberately does not install power-profiles-daemon. Fedora 44 ships tuned-ppd, which provides the same ppd-service and the same net.hadess.PowerProfiles D-Bus interface GNOME talks to, and the two packages conflict outright. The only thing lost is the powerprofilesctl CLI; tuned-adm is the equivalent.

Not automatic

Three things Fedora doesn't package, and the script won't install behind your back: Ghostty (built by linux/ghostty.sh), powerlevel10k (a git clone), and JetBrainsMono Nerd Font (a release zip into ~/.local/share/fonts, then fc-cache -f).

Layer 09 · Maintenance

Keeping it honest

A handful of scripts cover everything: one checks the rice is actually running, one re-links it onto a fresh machine, two prove the claims the repo makes about itself, one switches the palette everywhere at once, and one records what it all looks like. All exit non-zero when something is genuinely wrong.

Repo ~/.dotfiles Platforms macOS + Fedora Tapes 4

The scripts

One palette

Thirteen surfaces mirror the colours, in nine different notations — Ghostty's #rrggbb, SketchyBar's 0xAARRGGBB, Zed's #rrggbbaa, CSS, ANSI truecolor triplets. They were mirrored by hand until the themes landed, which made eight palettes 104 files that could drift with nothing to catch it. Each one is a .tmpl beside its output now; theme renders them and test/theme.sh fails if a rendered file stops matching its template.

Two halves

rice-doctor is a dispatcher: common/bin/rice-doctor picks macos/bin/ or linux/bin/. The output shape is identical on both; the checks underneath share almost nothing, because the layers don't.

Rule

Secrets live in ~/.config/secrets.zsh at mode 600, gitignored and sourced from .zshrc. The doctor fails loudly if a key ever creeps back into a tracked file.

Captures

VHS points ZDOTDIR at its own temp rc, so ~/.zshrc never loads and none of the rice appears. Every tape re-execs into a real interactive shell first — and any pager-capable command needs --paging=never, or the recording hangs forever waiting on a keypress.
